# DIYOR BURGER — финальная спецификация экранов

> **Назначение документа:** это визуальный и продуктовый источник истины для публичной части DIYOR BURGER. Он описывает 23 приложенных референс-экрана по отдельности: композицию, цвета, типографику, иконки, изображения, интеракции и связанные состояния.
>
> **Важно:** референсы задают внешний вид, но не отменяют рабочую логику проекта: цены и наличие берутся из данных, доставка и зоны — динамические, итог заказа пересчитывается сервером, а заказ не считается отправленным, пока пользователь сам не подтвердил отправку в WhatsApp.

### 2.2. Типографика и геометрия

- Базовый язык интерфейса — русский; тексты должны совпадать по смыслу и регистру с референсами.
- Заголовки: очень жирные, плотные, почти чёрные; в hero — белые с ключевыми словами золотого цвета.
- Основной мобильный ритм: внешние отступы `16–24px`, промежутки между секциями `18–28px`.
- Радиусы: hero `24–28px`, обычные карточки `20–24px`, чипы и price pills `999px`, поля `16–20px`.
- Тени спокойные и тёплые: не серые «материальные», а очень размытые коричневатые на белой поверхности.
- Минимальная touch-area любого интерактивного элемента — `44×44px`.
- Публичный мобильный shell не должен иметь горизонтального скролла на ширинах `320`, `360`, `375`, `390` и `430px`.

### 2.3. Иконки и изображения

- Используются линейные, чуть неровные «живые» контурные иконки из `папка иконок/` / `public/assets/icons/`, а не случайные emoji или библиотека с другим стилем.
- Стандарт: 2–2.25px тёмный контур, оранжевый — только для акцентов; белый контур — на тёмном герое.
- Круглые action-кнопки: плюс/минус/сердце/корзина размещаются строго по центру, без текстовой подписи.
- Снимки экранов — **не** фон и не ассет интерфейса. Для товара/баннера применяются отдельные оригинальные изображения, заданные из админки/Storage.
- Генерация недостающего food media допустима только как самостоятельный asset с чистыми правами, одинаковой «рекламной» студийной стилистикой: тёмный шоколадный bokeh либо мягкий кремовый фон, резкий продукт, без текста, без поддельных логотипов.

### 2.4. Общие паттерны shell

**Верхняя панель.** Белый фон; высота около `72–88px`; в зависимости от контекста: hamburger или back слева, логотип, заголовок/локация, search и cart справа. У корзины — круглый оранжевый count badge. На детальных страницах название товара центрируется только когда это не ломает читаемость.

**Нижняя навигация.** Белая фиксированная/липкая панель с лёгкой верхней тенью и пятью равными пунктами. Иконка сверху, подпись снизу. Активный пункт оранжевый, остальные чёрные/серые. Состав для основной линии: Главная, Меню, Комбо, Корзина, Профиль; в старшем наборе reference встречаются вариации «Избранное» и «Контакты» — эти состояния допускаются только когда маршрут реально доступен.

**Продуктовые карточки.** Фото занимает верх или левую половину; название — жирное; описание — серое и ограничено по строкам; цена — жёлтая pill; add — круг с плюсом. Изображение не должно растягиваться, нужна `object-fit: cover` и стабильный кроп.

**Data-driven правило.** Названия категорий, товары, варианты пиццы, цены, активность, баннеры, зоны, контакты и адреса выводятся из текущего data layer/admin. Тексты и сумма в референсе — композиционные примеры, не источник бизнес-данных.

## 4. Матрица компонентов, которые должны быть едиными

| Компонент | Где используется | Неподвижные правила |
|---|---|---|
| `SiteHeader` | все public routes | правильная вариация left/action/title, logo, badge, accessible labels |
| `BottomNavigation` | главная, меню, листинги, cart, favorites, contacts | 5 equal tabs, корректное active state, safe area снизу |
| `HeroBanner` | home, категории, cart, checkout, contacts | dark chocolate bokeh + foreground food, радиус 24–28, white/gold copy |
| `ProductCard` | menu, categories, search, favorites | data-driven image/name/price/availability; тип card зависит от screen layout |
| `AddControl` | product cards, cart, detail | plus circle / quantity stepper без непредсказуемых мутаций |
| `PricePill` | все товарные surface | gold fill, nearly black heavy text, сомони для UI |
| `CheckoutSummary` | cart, checkout, review | preview в cart; server-validated values в review |
| `DiyorIcon` | весь shell | только согласованный line-icon набор и цветовые состояния |

## 5. Неподлежащие подмене правила логики

1. Деньги хранятся в diram, форматируются в UI как сомони. Никакой цены из DOM/localStorage как источник истины.
2. Публичные данные показывают только active/allowed menu, banners, zones и settings согласно RLS/data layer.
3. Cart/favorites могут быть локальными, но перед заказом product, variant, availability, zone, fee и total перепроверяются сервером.
4. Delivery fee и free-delivery threshold вычисляются от subtotal товаров: pickup = 0; delivery = 0 при достигнутом threshold, иначе fee выбранной active zone.
5. Номера телефона нормализуются существующей Tajik-phone logic; WhatsApp destination берётся только из server settings.
6. Admin регулирует каталог, варианты, combo components, active status, delivery zones, settings, banners и media links. UI не должен зависеть от «Кушониён», «Вахш» или «Бохтар» в коде.
7. Нельзя показывать fake metric, fake order status, fake address, fake availability или fake zero, если источник данных недоступен.

## 6. Итоговый checklist визуальной приёмки

Для каждого из 23 экранов перед завершением визуального этапа проверить в браузере, а не только по коду:

- [ ] выбран правильный header variant: logo, back/hamburger, title, search/location/cart;
- [ ] есть все видимые из референса блоки в том же порядке;
- [ ] совпадает иерархия white / chocolate / gold / soft-cream поверхностей;
- [ ] используются именно соответствующие иконки и их состояния, а не похожие символы;
- [ ] карточки имеют корректную геометрию, радиусы, тени, crop и text clamping;
- [ ] bottom nav не перекрывает CTA, последний item и iOS safe area;
- [ ] на 320/360/375/390/430px нет horizontal overflow и touch targets не меньше 44px;
- [ ] отсутствие данных/пустая корзина/нет результатов/disabled product выглядят как отдельные честные состояния;
- [ ] action действительно выполняет заявленное действие и не противоречит server validation;
- [ ] секреты, service-role key и реальные личные данные не попадают в client bundle, screenshots или логи.
